# Explorer：M 参照から推定ロジックをたどる（Issue #30）

作成日：2026-09-07。公開ページの参照チップ M1〜M6（生成した成果物）をクリックすると、右パネル（スマートフォンでは下部シート）に「この推定結果の作り方」を表示します。数値モデル・公開確率・配布データは変更していません。追加したのは `site/index.html` のコード（約 37 KB）だけで、説明用データは追加していません。

## 1. 表示内容

| 項目 | 内容 |
|---|---|
| 見出し | 成果物名（参照 ID の M1/M2 は基準所得配列／最終所得配列で、実験モデル名の M1/M2/M12 とは別物。見出しに成果物名を併記） |
| データ版・条件 | `graph.json` の `dataset_version`・モデル版、地域と選択属性、年次、分母・単位、上流 M、入力統計 S/G |
| 工程の流れ図 | 入力統計／上流 M → 加工・補完 → 推定・整合 → 出力 をボタンで並べ、クリックで開く。各工程に「観測値／仮定／推定値／出力」のラベル |
| 工程の中身 | 平易な説明、現在の選択条件の値（既存の計算関数から取得）、分布が変わる工程は前後を同じ尺度の棒グラフで比較、技術的な詳細（折りたたみ）、参照データのチップ |

## 2. 導出レジストリと現行コードとの対応

`MODEL_DERIVATIONS`（`site/index.html`）は書誌情報 `SRC` とは別の構造で、成果物・上流・入力・工程（種別、ラベル、説明、値の関数）・仮定・検証・コード・METHOD を持ちます。工程の依存関係は生成コードと照合しています。

| 参照 | 成果物 | 上流 | 生成コード | 値の取得元（ページ内） |
|---|---|---|---|---|
| M1 基準所得配列 | `model_arrays.npz` counts_by_sex | なし | `build.py`（地位別形状の混合 q → 県 × 性別 × 年齢の公表構成へ IPF で校正）/ `estimator.py` fit_status, status_income_shapes, mixture, calibrate | `dist()` の cC（校正後の M1）、`G.ess`（公表分布＝校正の目標）。混合直後の q は未収録と表示 |
| M2 最終所得配列 | `final_arrays.npz` counts_by_sex | M1（比較の基準。入力ではない） | `estimator.run`：同じ混合 q に学歴・産業の傾きを掛けてから校正（`mixture(inp, W, cp, tilt)` → `calibrate` → `tax_project(β=0)`） | `dist()` の cD（校正後の M2）、`incDist()`（非就業を含む）。傾けた混合 q_tilt と傾きの中間値は未収録と表示。比較は「校正後どうし（M1 基準 → M2）」と明記 |
| M3 学歴別 | `education_leaf_arrays.npz` / `municipality_model_v2.npz` | M2 | `build_education.py` | `eduPop()`、`seedTab()`、`eduTab()`（ページ内の同じ IPF） |
| M4 就業・産業（出力の行は適用した条件だけをラベルにし、就業状態・地位・産業を選んだときはその条件付き確率を別行で表示） | `employment_a.npz` ほか | M3, M1 | `build_employment.py` block | `empCounts()`、`empBlock()`（葉は再計算、反復回数と周辺誤差を表示）、`empSeedShape()` |
| M5 世帯 | `household_b/<code>.npz`, `<code>_population.csv.gz` | M4 | `build_household.py`, `household_sample.py`, `export_household_web.py` | `web/household/<code>.json`（3 地域のみ） |
| M6 勤務地 | `workplace_c.npz`, `web/workplace/*` | M4 | `build_workplace.py`, `persona_v4.py`, `export_workplace_web.py` | `wpCompute()`、`wpCondition()`（両モード） |

## 3. 到達経路と戻り

- 属性パネル・辺パネル・年収帯の段階図にある M チップ、参照一覧（データソース）の各 M の「導出を見る」、導出パネル内の上流 M チップから開けます。S/G のチップは従来どおり参照一覧の該当行へ移動します。
- パネル内のパンくず（元のパネル › M4 › M3 …）と「戻る」で元の属性条件・パネルへ戻り、開いたチップにフォーカスを戻します。既にたどった M へ再度進む場合はスタックを巻き戻すため循環しません（深さ上限 8）。
- 閲覧しても選択条件・分布は変わりません（値は現在の配列と計算関数から読み出すだけで、状態を書き換えません）。

## 4. 検証（`tests/web_derivation_check.cjs`、`docs/experiments/explorer_derivations_verification*.json`）

7 つの文脈（港区 35〜39歳・男・大学等、遠軽町の全年齢、大阪市（政令市）、双葉町（人口 0）、港区の学歴不詳、港区の完全失業、東京都の県集計）× M1〜M6 で、表示、全工程のクリックとフォーカス、値の一致（M2 の出力＝ページの年収分布、M3 の出力＝学歴を選んだ年収分布、差 1e-12 以内）、M4 の出力の行が適用した条件だけをラベルに持ち、値がページの条件付き人数と一致すること（港区・35〜39歳・男・完全失業：P(就業者｜35〜39歳・男) 96.7% と P(完全失業者｜…) 1.9%、正規 × 情報通信業の行）、M1 の工程順（混合＝未収録 → 校正）と M2 の工程順（傾きを混合に掛ける → 校正、M1 は入力でなく比較の基準）、上流 M への移動と戻り、フォーカスの復帰、閲覧前後の条件・分布の不変を確認。M チップからの遷移と戻りでフォーカスがチップに戻ること、循環（M4→M3→M2→M1→M4）でスタックが巻き戻ること、参照一覧に 6 つの「導出を見る」があること、段階A/B/C のない schema 2 データでも同じ検証が通ることを確認。既存の再現検証（`web_employment_check.cjs`、`web_workplace_check.cjs`、操作シナリオ）も合格。ヘッドレス Chrome で PC と 390px 幅の表示（流れ図は縦並び）を確認。

追加容量：`index.html` +37 KB（データの追加なし）。処理時間：値はキャッシュ済みの配列・計算から取り出すため、段階A/B/C のファイル取得を除き即時。世帯・勤務地の値は該当パネルと同じファイルを必要時に取得します。

## 独自仮定の検証状況と工程ごとの参考文献（Issue #32、2026-09-07）

### 仮定レジストリ `ASSUMPTIONS`

M1〜M6 に表示する独自仮定に安定した ID（A01〜A19）を付け、`ASSUMPTIONS` に内容・導入理由・適用される工程と属性・母集団、検証の分類（**直接検証済み／間接評価のみ／未検証**）とその理由・限界、4 種類の検証方法（公表統計との整合、推定に使わなかった統計との比較、仮想人口での復元、感度分析・比較実験）ごとの状況（実施済み／未実施／対象外と理由・結果・対象）、対象・年次・モデル版、検証コードとレポートへのリンクを持たせた。`MODEL_ASSUMPTIONS` で各 M に対応付け、各工程は `asm` で使う仮定 ID を参照する（A04 全国形状の移植は M2・M3・M4 で共有、A07 学歴不詳は M3・M4 で共有）。

仮定のラベルと本文はボタンで、クリックすると詳細パネル（スマートフォンは下部シート）に、上部の要約（分類と理由）、導入理由・適用範囲・使う成果物・対象とモデル版・限界・閲覧中のデータ版、検証方法ごとの表、分類の規則、リンクを表示する。「戻る」で元の M と開いていた工程に戻り、フォーカスは押した仮定に復帰する。閲覧しても条件・分布は変わらない。

現在の地域に結果がない場合は表の中で明示する：86 都市の評価は `graph.munis[].v` で判定し、対象外の市区町村では「評価対象外。この地域の結果はない」、世帯の 3 地域・港区の 13-2、独立統計（市区町村単位）も同様。大都市等 290 地域（勤務地）は対象地域の一覧を配布していないため「判定できない」と表示する。

分類の根拠は既存レポートと照合した（docs/experiments/validation_m12.json、synthetic_recovery_m12.json、employment_a_verification.json、employment_a_synthetic.json、household_b_population_*.json、workplace_c_verification.json、validation/education_sensitivity.json）。モデル全体の成績（86 都市の TV、独立統計の相関）は仮定単独の実証として扱わず、「間接評価のみ」の内容として記載する。「直接検証済み」は A05（係数の採用：事前登録した規則で out-of-fold と独立統計により選んだ）と A16（通勤区分内の産業別勤務地：推定に使わない第9・10表で推定量そのものを比較）の 2 件で、いずれも対象範囲（都市の就業者の年収構成・市区町村の相対水準、大都市等 290 地域）の外は保証しない旨を併記する。v2.0 時点の感度分析（学歴別形状）は「旧版の参考評価」と明記する。

### 参考文献の工程への紐付け

M 全体の直下に論文を一律表示する構成をやめ、`MODEL_LITERATURE`（書誌・リンク・確認箇所）と工程ごとの `lit`（参考にした点、本実装との違い）に分けた。IPF の論文（Lovelace ほか 2015）は M1・M2 の校正、M3 の配分、M4・M5・M6 の反復比例調整の工程に、所得割当ての論文（杉浦ほか 2019）は M1 の混合と M4 の配分に、世帯合成の論文（原田ほか 2018）は M5 の期待人数表に、勤務地割当ての論文（堀上・村田 2026、公開抄録のみ）は M6 の反復比例調整に表示する。各工程の「手法の参考文献（この工程）」には著者・年・題名・リンク、確認箇所、参考にした点、本実装との違いを示し、独自仮定の実証や日本の推定精度の保証ではない旨を添える。仮定の詳細にはその仮定の検証情報だけを表示し、仮定自体を支持する論文を確認した場合にのみ対象と支持範囲を明示して追加する。

### 検証（`tests/web_derivation_check.cjs`）

レジストリの整合（M と工程が参照する仮定 ID・文献キーの存在、各仮定の分類・4 方法・リンクの必須項目、未参照の仮定がないこと、A04 の共有）、M4 の工程から A10 を開いて 4 行の表と「未検証」「分類の規則」が出ること、戻ると M4 の同じ工程に戻りフォーカスが仮定のボタンへ復帰すること、閲覧前後の条件と分布の不変、遠軽町で「評価対象外」・那覇市で「86 都市に含まれる」の表示、A04 の「旧版」表記、A05 の「直接検証済み」と限界の併記、M レベルに論文一覧がなく各 M の工程に文献があることを確認。段階A/B/C のないデータでも合格。
